# DriveLens 产品审计报告（产品经理视角）

审计时间：2026-08-13 ｜ 审计基线：当前主干代码（深色科技风 UI + 真实 RCA 派生案例接入后）

---

## 0. 一句话产品定义

DriveLens 不是"AI 自动找根因"工具，而是**无人车异常行为的证据链工作台**：把几秒的异常变成可回放、可反驳、可协同、最终由人确认的工程证据链。

这一定义是理解全篇审计的前提——它的价值不在"算得准"，在"过程可信"。

---

## 1. 解决了什么实际问题

目标用户：无人车研发 / 测试工程师（以及需要评审诊断结论的技术负责人）。

| 真实痛点 | DriveLens 的解法 | 解决深度 |
| --- | --- | --- |
| 异常只发生几秒、难复现 | 触发前后 40 秒多源信号同轴回放 + 光标取值 | ✅ 完整 |
| 日志/状态机/现场画面分散，靠人脑拼 | 统一 snapshotId，一处诊断处处消费 | ✅ 完整（机制层） |
| 结论无法服众、跨团队扯皮 | Top3 疑因竞争 + 每条证据正负贡献账本 | ✅ 完整 |
| "AI 说的"在安全场景不可信 | 确定性计分，模型只解释；证据门禁不到门槛禁止确认 | ✅ 完整（核心差异点） |
| 第一次结论错了没人敢推翻 | 补证改判：新证据逐条重算、可撤回 | ✅ 完整（演示高潮） |
| 历史经验难复用 | 故障指纹 + 相似案例（只复用核验动作，不继承根因） | ⚠️ 机制成立，案例库为合成 |
| 真实数据上表现如何 | 10 个真实 RCA 派生案例已接入 | ❌ 0/10 原始时序，只能"诚实停止" |

**结论：合成数据链路上，痛点解法完整且自洽；真实数据链路上，目前只解决了"边界诚实"，尚未解决"诊断能力"。**

---

## 2. 产品意义

1. **对比赛**：赛题评分规则（SCORING_RUBRIC）的硬红线是"虚构信号即失败、证据不足时归因即失败"。DriveLens 的"证据门禁 + 诚实停止 + 不伪装远程成功"与红线逐条对齐。大多数参赛方案会包装准确率数字，DriveLens 反向选择"可证伪的工程流程"，这是差异化，也是风险（见 §4）。
2. **对行业**：安全关键场景的 AI 正确姿势不是"替代工程师"，而是"组织证据、暴露不确定性、把终裁权留给人"。这个范式本身有布道价值。
3. **对团队**：统一快照、门禁、账本的工程纪律，是真能沉淀进研发流程的东西。

---

## 3. 痛点与抓手

**最痛的点（用户视角）**：异常诊断的结论"说不清、辩不明、推不翻"。工具散、证据散、责任散。

**三个抓手（按强度排序）**：

1. **证据门禁**——把"可信"从口号变成制度：6 项条件不满足，系统物理上禁止确认。这是产品的灵魂。
2. **补证改判**——新证据可以推翻第一次排序（71→39 / 68→86）。这是演示中唯一能让评委"哇"出来的时刻，因为它演示的是"系统允许自己错了被纠正"。
3. **统一快照 + 诚实停止**——服务端拒绝旧快照与越门禁写入；真实数据上宁可不答也不错答。

抓手的组合效应：三者共同构成"可信边界"叙事，这是相对其他参赛方案的护城河。

---

## 4. 目前存在的问题（按优先级）

### P0 — 影响比赛结果或产品成立性

1. **真实数据模式"能看不能用"**：10 个真实案例 0/10 原始时序覆盖，进入真实模式后诊断链路断裂，只剩边界声明。评委必然追问："接入了真实数据却不能诊断，意义何在？" 当前答案（证明边界诚实）是防御性的，不是价值性的。
2. **核心价值必须靠演示脚本触发**：产品的灵魂是"补证改判推翻排序"，但冷启动用户自己乱点时，只看到"案例列表 + 曲线 + 三张疑因卡片"，大概率错过高潮。产品自身不会说话，依赖 115 秒口述稿。
3. **大分数存在"类概率"误读风险**：尽管到处声明"证据匹配度 ≠ 根因概率"，71/86 这种大数字在视觉上是页面最抢眼的元素，人类本能会把它读成置信度。声明文字对抗不了视觉权重。

### P1 — 影响理解效率

4. **首屏信息密度过载**：顶部 pitch 条 + 四步导航 + 三栏 + 事实条 + 图表 + 规则命中 + 右侧账本/门禁/核验框，同时争抢注意力。层级多 = 没有层级。
5. **双数据源切换的认知断层**："演示数据 / 真实 RCA 派生案例"切换后，同一套界面一会儿能算分一会儿不能算，用户需要自行理解为什么。
6. **非专家路径缺失**：界面为 domain 工程师设计，评委（未必懂 CIPV/MCAP）缺少 30 秒理解通道。

### P2 — 工程与打磨

7. 单文件膨胀：DriveLensApp.tsx 941 行、drivelens.css 4334 行，迭代维护成本在累积。
8. 飞书协同是"待验收的集成"而非"已验证的集成"，演示时本地降级状态可能被误读为未完成。
9. 三个合成案例场景同质化（均偏纵向控制），真实数据已有 ACC/FCW/AWB/LCC 四域但无诊断深度。

## 6. 优化方向（按 ROI 排序）

1. **把高潮前置**：默认展示"补证前后"对比视图（Before/After 并排），而不是等用户点"补入证据"。让"可推翻性"成为首屏的一部分。
2. **分数降权，排名升权**：把大号分数改为证据强度条 + 排名徽章，数字缩小并紧跟"匹配度≠概率"角标。从视觉上根除误读。
3. **真实模式给出"解锁预览"**：边界声明之外，灰化展示完整诊断链 + 标注"接入原始 MCAP 后解锁此能力"。把防御性叙事变成路线图叙事。
4. **30 秒自演示模式**：自动播放 现场还原→疑因竞争→补证改判→协同 四幕，评委坐下无需操作即可看懂。
5. **一页纸评委摘要导出**：当前判断、证据边界、拒识理由、下一步，一键导出 PDF/图片。
6. **工程减负**：拆分 DriveLensApp 与 CSS 为模块；为 6 个核心组件补快照测试。

## 7. 最终判断

**作为比赛作品：第一梯队。** 设计哲学与赛题评分红线逐条对齐，工程完成度高，可信边界叙事在同场方案中几乎没有对手。

**作为产品雏形：方向正确，但有一道未跨过的门槛。** 产品的全部价值建立在"证据链流程"上，而这套流程目前只在合成数据上闭环。真实数据模式是"诚实但不可用"的——这在比赛叙事里是加分项，在产品逻辑里是致命gap。

**一句话判断**：DriveLens 证明了"可信诊断流程"可以被工程化，但还没有证明"这套流程在真实数据上能产出诊断价值"。复赛的最大胜负手，不是再加功能，而是把真实数据从"边界演示"推进到"至少一个案例的全链路诊断"——哪怕只有一个。
